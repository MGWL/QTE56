# Руководство по генератору QTE56 (для AI-агентов)

> ↑ Навигация: [AGENTS.md](../AGENTS.md) → [GENERATOR_KNOWLEDGE_TRANSFER.md](../GENERATOR_KNOWLEDGE_TRANSFER.md)

> Генератор создаёт C++ wrapper-файлы (.h/.cpp/.pro) и D-модуль (gen_*.d)
> из заголовочного файла Qt. Пользователь — AI-агент; человек только ревьюит.
> Документ описывает устройство, режимы, проверки и типовые сценарии.

Версия генератора: `2.1.0-knowledge` (см. `geninfo.GENERATOR_VERSION`).
Состояние на 2026-08-02: после рефакторинга на модули + preflight + `--augment` + `scan_augment.py`.

---

## 1. Карта модулей `generator/`

| Файл | Роль |
|---|---|
| `main.py` | Точка входа. Тонкий оркестратор: argparse → фазы `[1/5..5/5]`. Никакой логики генерации внутри. |
| `checks.py` | Preflight-проверки (фаза 2). `CheckResult(status=OK/WARN/FAIL)`. Любой FAIL → выход до записи чего-либо. |
| `planner.py` | Планирование: фильтрация методов, суффиксы перегрузок, skip унаследованных, регистрация функций в реестре (in-memory). |
| `cpp_texts.py` | Тексты .h/.cpp/.pro + примитивы одной функции (`_method_h_line`, `_method_cpp_lines`, `_lambda_*`) — их же использует augment. |
| `d_generator.py` | Класс `DGenerator` — полный текст gen_*.d (импорты, load-функция, класс, сигналы, events). |
| `geninfo.py` | Блок GENERATOR-INFO (версия, команда запуска, skipped-unsupported). |
| `augment.py` | Режим `--augment`: патч только с недостающими методами существующего модуля. |
| `fileops.py` | Запись файлов, unified diff, `--patch` по маркерам AUTO-GENERATED-*. |
| `registry.py` | `Registry` — functions.csv: загрузка, выделение индексов, сохранение (дописывает, не переписывает). |
| `qt_parser.py` | Парсер Qt-заголовков → `QtClass` (методы, сигналы, конструкторы, supported/unsupported). |
| `type_map.py` | Маппинг C++ типов → D типы; что unsupported — метод пропускается с причиной. |
| `qt_knowledge.py` → `knowledge/qt_knowledge.json` | База знаний по всем 1348 заголовкам Qt: иерархия, enum'ы, value-типы. Без неё — fallback на эвристики. |
| `qt_hierarchy.py` | `D_PARENT_FULL`, `INTERMEDIATE_METHODS` — D-наследование и skip-списки. |
| `events.py` | Описание виртуальных Qt-событий для генерации proxy-класса (EventId, сигнатуры). |
| `knowledge_access.py` | Ленивый singleton-доступ к `knowledge/qt_knowledge.json` (`get_knowledge()`). |
| `test_new_class.py` | Harness: генерация во временный каталог на КОПИИ реестра + g++ syntax + dmd compile. Реестр не трогает. |
| `scan_augment.py` | Скан всех модулей реестра на полноту покрытия: для каждого прогоняет `main.py --augment` (без `--apply`, на копии CSV) и собирает отчёт по «дырявости». Запуск: `py scan_augment.py [топN]`. |
| `scan_ldc2_bugs.py` | Скан `d/gen/gen_*.d` на баги совместимости DMD/ldc2 (super(true/false/_noOp) и т.п.). |
| `reindex.py` | Реиндексация pFunQt-индексов с block_size=200 (сжатие дыр). Опасная операция — только осознанно. |
| `merge_dlls.py` | Генерация merged `.pro` (6 merged DLL) из поклассовых проектов. |
| `make_build.py` | Генератор build-скриптов/сниппетов/скелетов приложений (см. `make_build_guide.md`). |

## 2. Пайплайн main.py

```
[1/5] parse header      qt_parser → QtClass; FAIL: файл не найден / класс не найден
[2/5] preflight checks  checks.py: header, registry, dll-name, index-start, augment
[3/5] plan methods      planner.py: методы/сигналы → индексы (in-memory реестр!)
[4/5] generate texts    cpp_texts.py + DGenerator (только в память)
[5/5] write + registry  запись файлов и reg.save(); при --dry-run пропускается целиком
```

Ключевое свойство: **FAIL на фазах 1–3 = ноль побочных эффектов**. Запись файлов
и реестра происходит только в фазе 5. `--force` обходит FAIL проверок (кроме
невозможности распарсить заголовок).

Реестр мутируется in-memory уже в фазе 3 (`reg.add_class_functions`), но на диск
попадает только через `reg.save()` в фазе 5. Поэтому `--dry-run` безопасен.

## 3. Реестр functions.csv — железные правила

1. **Индекс функции никогда не меняется.** Новые функции — только новые индексы.
2. **Настоящий реестр — `registry/functions.csv` (UTF-8!).** Один CP1251-байт роняет `qte`.
3. **Любые эксперименты — только на копии:** `--csv /tmp/copy.csv`.
   Перед экспериментом: `cp registry/functions.csv registry/functions.csv.bak-<дата>`.
4. Новые классы — в дыры нумерации через `--index-start`
   (актуальные дыры: `qte index gaps`). Превышение `PFUNQT_SIZE` (25000) — FAIL.
5. Если класс уже в реестре, генератор **переиспользует существующие имена/индексы**
   (проверка `reused-names` сообщает сколько). Осторожно: имя/индекс те же, а
   сигнатура в новом C++ может отличаться от старой DLL — см. §8, баг №1.
6. После любых изменений реестра: `qte index check` (коллизии) и `qte check all`.
7. **Суффиксы перегрузок — длинные** (`_qpointf_qpointf`, `_qrect_qt_globalcolor`,
   `_qt_penstyle`): полное имя типа, коллизии практически исключены; счётный
   суффикс `…2` — только страховка. Старые короткие суффиксы в реестре
   не меняются.

## 4. Режимы запуска

### 4.1 Полная генерация нового класса

```bash
cd generator/
py main.py C:/Qt5_13_2/.../include/QtWidgets/qfoo.h \
    --module QFoo --dll qte56_qfoo.dll --index-start 21400
```

- `--dll` для нового класса задавать явно (иначе шаблон `qte56_<cls>.dll`).
- `--index-start` — начало дыры из `qte index gaps`.
- `--parent-header <path>` (repeatable) — добавить публичные методы родителя в DLL.
- `--d-parent <QWidget>` — D-родитель (обычно авто: `qt_hierarchy` → knowledge).
- После генерации: пересобрать DLL, создать тест в `test/`, `qte check all`.

### 4.2 Harness (проверка нового класса без риска)

```bash
py test_new_class.py <header.h> --module QFoo --index-start 21400 [--keep]
```

Генерация во временный каталог на копии реестра + g++ + dmd. Реестр не меняется.
**Всегда начинайте с harness**, прежде чем реальная генерация.

### 4.3 --augment: дополнение существующего модуля

Сценарий: модуль уже есть (старый генератор/ручной), а генератор нашёл в
заголовке Qt больше поддерживаемых методов. augment НЕ переписывает файлы —
формирует `augment_<cls>.patch.txt` для ревью.

```bash
py main.py <header.h> --module QShortcut --augment           # патч
py main.py <header.h> --module QShortcut --augment --apply   # + CSV в реестр
```

«Новые» определяются так:
- методы — `func_name` отсутствовал в реестре до планирования;
- сигналы — `connect_<name>` отсутствует в существующем `d/gen/gen_<cls>.d`.

Фильтры дублей (2026-07-26):
- **C++ тело**: если тело новой функции побайтово совпадает с телом в
  существующем `.cpp` модуля — это тот же Qt-метод под другим именем
  (старые суффиксы `_p`/`_rect`); попадает в секцию [7], не в патч;
- **D-переименование**: если D-сигнатура нового метода (имя + типы параметров)
  уже есть в старом gen-файле — метод получает суффикс из func_name
  (`drawLine_qpointf_qpointf`), иначе D-ошибка перегрузки.

Секции патча:
1. CSV-строки (только новые индексы, в дыру после существующего блока);
2. C++ объявления для .h (макрос `<CLS>_API` — сверить с существующим .h);
3. C++ реализации для .cpp;
4. D mixin-строки для load-функции;
5. D-методы (вставить перед `// ===MANUAL-METHODS-START===`);
6. Импорты из генерированного файла (сверить с текущими в gen-файле).

Порядок применения: ревью патча → перенос в cpp/h/d → `--apply` (или CSV вручную)
→ пересборка DLL → тест модуля → `qte check all`.

Ограничения:
- модуль обязан быть в реестре (иначе preflight FAIL);
- ownership-overload'ы и события (setEventHandler) в сниппеты не попадают —
  только обычные методы и сигналы;
- патч — это предложение, не автомат: в старом модуле методы могли быть
  сознательно не забиндены (см. orphans в AGENTS.md §18).

### 4.4 Прочие флаги

- `--dry-run` — всё посчитать, ничего не писать (реестр не сохраняется).
- `--diff` — unified diff генерируемого vs существующих файлов.
- `--patch` — обновить только блоки между AUTO-GENERATED-* маркерами
  (работает только с файлами нового генератора; MANUAL-METHODS сохраняются).
- `--info` — только сводка по классу из заголовка.
- `--no-cpp` / `--no-d` — пропустить соответствующий вывод.

## 5. Preflight-проверки (checks.py)

| Проверка | OK | WARN | FAIL |
|---|---|---|---|
| `header` | класс найден, методы есть | 0 поддерживаемых методов | файл не найден |
| `registry` | коллизий нет | дубликаты имён (2 известных — норма) | коллизии индексов |
| `dll-name` | имя из реестра/шаблона | модуль размазан по DLL; --dll ≠ реестр | — |
| `index-start` | свободен | класс уже в реестре (флаг игнорируется) | вне диапазона / занят |
| `augment` | — | — | модуль не в реестре |
| `reused-names` (пост-план) | N имён переиспользованы | модуль/DLL ≠ плану | — |

Поведение dll-name: для класса, уже существующего в реестре, имя DLL берётся
**из реестра**, а не из шаблона (фикс бага 2026-07-26: QShortcut получал
`qte56_qshortcut.dll` вместо реальной `qte56_shortcut.dll`).

## 6. Что генератор пишет в файлы

- **GENERATOR-INFO** (в .h/.cpp/.pro/.d): версия, timestamp, полная команда
  запуска, источник d_parent, версия knowledge, список skipped-unsupported
  с причинами. По нему восстанавливается, как генерировался класс.
- **Маркеры** в gen_*.d: `AUTO-GENERATED-LOAD-FUNC-START/END`,
  `AUTO-GENERATED-CLASS-START/END`, `MANUAL-METHODS-START/END` — для `--patch`.
- Lifecycle: для QObject-наследников create оборачивается в `qte_createTracked()`
  (линковка с qte56_foundation в .pro). Value-классы (QPointF, QRectF) — без parent.

## 7. Типовые задачи AI-агенту

**«Добавь новый класс QFoo»** → harness → если PASS: полная генерация с
`--index-start` из дыры → пересборка DLL → тест → `qte check all`.

**«Проверь, полон ли модуль QBar»** → `--augment` (реестр НЕ меняется) →
показать пользователю секции патча.

**«Добавь пропущенные методы в QBar»** → `--augment` → ревью патча → перенос
сниппетов вручную в существующие cpp/h/d → `--apply` → пересборка DLL → тест.

**«Перегенерируй модуль QBar»** → НЕ делать без явного указания: перегенерация
= полная перезапись, ручные правки сгорят (см. AGENTS.md: закомментированные
геттеры, orphans). Сначала `--diff` и анализ по категориям.

## 8. Известные ловушки

1. **Индекс переиспользован, сигнатура изменилась.** Генератор матчит функции
   по имени. Если в старой DLL `qteQFoo_create(parent, wstr, len)`, а новый
   план даёт `qteQFoo_create(parent)` — индекс тот же, ABI другой. Подмена
   только gen-файла без пересборки DLL = crash. Проверка `reused-names`
   сообщает факт, но сигнатуры в CSV нет — сверять глазами со старым .cpp.
2. **Новые индексы без пересборки DLL = crash** (pFunQt[idx] = null).
   Подменили gen-файл — пересоберите DLL до запуска.
3. **`--index-start` на существующем классе молча игнорируется** (WARN) —
   новые методы уходят в дыру после блока класса, а не туда, что указали.
4. **Merged DLL.** Метод добавлен в модуль из merged DLL (widgets/foundation/
   views/text/dialogs/mainwin) — пересобирается вся merged DLL, а не один файл.
5. **Harness наследует состояние CSV-копии.** Повторные прогоны на одной копии
   видят записи прошлых прогонов — для чистого эксперимента копию делать заново.
6. **Windows-консоль CP1251.** Русские WARN/OK в stdout могут отображаться
   кракозябрами — на файлы и реестр не влияет.

## 9. Верификация после любых изменений генератора

1. Эталонный прогон до изменений: 2 класса (напр. qshortcut.h + qpoint.h) на
   копии CSV, сохранить вывод.
2. После изменений — те же команды, `diff` вывода (игнорируя
   `timestamp`/`command` в GENERATOR-INFO). Вывод обязан совпадать.
3. `py test_new_class.py qshortcut.h --module QShortcut` — harness PASS.
4. Реестр побайтово не изменился (`cmp` с бэкапом), `qte index check` чистый.
