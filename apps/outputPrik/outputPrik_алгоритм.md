# Алгоритм программы outputPrik — формирование номеров выходных приказов

## 1. Назначение программы

Программа читает текстовый файл (экспорт из Excel, поля разделены символом `|`),
в котором каждая строка описывает одного человека (обучение/аттестация), и
**присваивает каждой строке номер выходного приказа** вида `N_K`, где:

- `N` — номер недели (от 1 до 99);
- `K` — порядковый номер приказа внутри этой недели.

Правило присвоения: **всем строкам с одинаковым «ключом недели» должен быть
присвоен один и тот же номер приказа**. Если номер уже существует — он
сохраняется; если нет — вычисляется новый (либо занимается первая свободная
«дырка» в уже использованных номерах недели, либо берётся `max+1`).

После обработки файл **перезаписывается под тем же именем** новым содержимым.

---

## 2. Коды возврата (обязательная часть контракта)

| Код | Значение |
|-----|----------|
| 0 | Успех |
| 1 | Неверные аргументы командной строки / входной файл не существует |
| 2 | Ошибка данных в строке Excel (показывается окно с полями строки) |
| 3 | Ошибка чтения/записи файла или иное ожидаемое исключение |
| 4 | Внутренняя ошибка (выход за границы массива и т.п. — «не должно случаться») |
| 5 | Входной файл пуст |
| 6 | После фильтрации не осталось ни одной строки, пригодной для обработки |

Ошибки показываются пользователю через окно сообщения (MessageBox), текст
которого перекодируется из UTF-8 в Windows-1251. При портировании допустимо
заменить на вывод в stderr/консоль, но коды возврата сохранить.

## 3. Входные данные

### 3.1. Аргументы

Программа принимает ровно один аргумент — **путь к входному файлу**.

- Консольная версия: `outputPrik <путь_к_файлу>`. Если аргументов не ровно 1 — ошибка, код 1. Если файл не существует — ошибка, код 1.
- GUI-версия (Windows): командная строка разбивается по пробелам, пустые куски отбрасываются; если аргументов нет — код 1. **Примечание:** в оригинале GUI-версия передаёт в обработку `args[1]` (второй аргумент) — при портировании использовать первый аргумент, если только не требуется бит-в-бит совместимость с багом.

### 3.2. Формат файла

- Текстовый файл в кодировке UTF-8 (допускается BOM `EF BB BF` — он удаляется из первой строки).
- Одна строка = одна запись. Пустые (после trim) строки пропускаются.
- Поля внутри строки разделены символом `|`. Минимум **12 полей** (индексы 0..11). Если полей меньше — ошибка данных (код 2).

Пример строки:

```
28|Страшинский|02.11.1994|13.01.2025|20250113|17.01.2025|20250117|3|очная|ГП|ПК250103017|3_4|
```

Используемые поля (по индексам после разбиения по `|`):

| Индекс | Смысл | Использование |
|--------|-------|---------------|
| 0 | Номер строки в исходном Excel | Сохраняется в выходную строку; показывается в заголовке окна ошибки |
| 1–5 | ФИО, даты (в т.ч. поле 4 — дата начала `YYYYMMDD`, поле 5) | Поле 4 входит в ключ недели; поля 0–5 выводятся в сообщении об ошибке |
| 6 | Дата (формат `YYYYMMDD`, напр. `20250117`) | Входит в ключ недели |
| 7 | **Номер недели** (число 1–99) | Входит в ключ недели; определяет неделю приказа; валидация |
| 8 | Форма обучения (напр. `очная`, `дистанционная`) | Входит в ключ недели |
| 9 | Подразделение/категория (напр. `ГП`, `ПК`, `ОС`) | Входит в ключ недели |
| 10 | № удостоверения либо текст | Поле фильтрации (см. п. 4.2) |
| 11 | **Существующий номер вых. приказа** вида `3_4` (может быть пустым) | Основа для присвоения номеров |

### 3.2.2. Какие поля влияют на присвоение номера приказа (с примерами)

Номер приказа определяется **шестью** полями строки. Пять из них образуют
**ключ приказа** — строки с одинаковым ключом обязаны получить один номер:

| Поле (название) | Индекс | Пример | Роль |
|---|---|---|---|
| **Номер недели** | 7 | `4` | Число `N` в номере `N_K`; входит в ключ |
| **Дата конца (YYYYMMDD)** | 6 | `20260123` | Входит в ключ |
| **Дата начала (YYYYMMDD)** | 4 | `20260119` | Входит в ключ |
| **Форма обучения** | 8 | `очная` / `очная Ч` / `дистанционная` | Входит в ключ |
| **Категория (подразделение)** | 9 | `ГП` / `ОС` / `УЦ` | Входит в ключ |
| **№ приказа (уже стоящий)** | 11 | `4_4` или пусто | Определяет, нужен ли новый номер, и какой |

Ключ = `pad3(неделя) + дата_конца + дата_начала + форма + категория`.
Пример: неделя `4`, `20260123`, `20260119`, `дистанционная`, `ГП`
→ ключ `0042026012320260119дистанционнаяГП`.

Поле 10 (№ удостоверения/Справка) на номер **не влияет** — оно решает только,
попадает ли строка в обработку вообще.

**Как поле 11 управляет присвоением (примеры из теста `test_holes.txt`):**

1. **Поле 11 заполнено** (`6_1`) → номер не меняется никогда (приказ напечатан).
   Строка `20|...|6|дистанционная|ГП|ПК...|6_1|` → выход `20||6_1|...` (новый номер пуст).
2. **Поле 11 пусто, у ключа уже есть номер** (другая строка с тем же ключом имеет `10_5`)
   → строка получает тот же `10_5` — добавленный задним числом человек попадает
   в уже существующий приказ.
3. **Поле 11 пусто, ключа нет, на неделе есть дырка** (заняты `6_1`, `6_3`)
   → строка получает `6_2` — дырка заполняется.
4. **Поле 11 пусто, дырок нет** (заняты `7_1`,`7_2`,`7_3`) → `7_4` (максимум+1).
5. **Поле 11 пусто, номеров на неделе нет вообще** → `5_1`.

**Примеры влияния полей ключа на группировку** (одна и та же неделя 4):

- `очная` + `ГП` и `дистанционная` + `ГП` → **разные** ключи → разные номера приказов.
- `очная` + `ОС` и `очная Ч` + `ОС` → **разные** ключи (форма отличается пробелом!).
- Одинаковые поля 4/6/7/8/9, но разные даты начала (`20260119` vs `20260120`)
  → **разные** ключи → разные приказы.
- Разница в ФИО, дате рождения, № удостоверения на ключ **не влияет** —
  такие строки собираются в один приказ.

### 3.2.1. Фактический формат файла от Excel (проверено на `tempfile_20260730_151204.txt`)

Реальный файл, который готовит Excel (анализ образца на 978 строк):

- **Кодировка: UTF-8 с BOM** (`EF BB BF`) — удаление BOM на шаге 1 обязательно.
- **Переводы строк: CRLF** (`\r\n`). При разбиении на строки нужно обрабатывать `\r\n` (splitLines в D убирает `\r`; при портировании убедиться, что `\r` не остаётся в конце полей — иначе в поле 11/12 попадёт `\r`).
- **Каждая строка оканчивается на `|`** — т.е. после разбиения получается 13 полей, последнее (индекс 12) пустое. Проверка «минимум 12 полей» это допускает.
- Реальные значения полей 8/9: формы обучения `очная`, `очная Ч` (с пробелом!), `дистанционная`; категории `ГП`, `ОС`, `УЦ`. Ключ недели может содержать пробел внутри (`очная Ч`), trim применяется только по краям.
- Поле 10 — номер удостоверения вида `ПК260104017` (буквы + 9 цифр — проходит `tstIsUd`).
- Поле 11 (`4_4`) либо пустое (в образце 32 строки из 978 без номера — именно им присваиваются новые номера).
- Поле 0 — номер строки Excel (в образце 2..979).
- Целевая платформа — **только Windows 32-bit** (оригинал собирается `dmd -m32`); при портировании достаточно 32-битной Windows-сборки, кроссплатформенность не требуется.

### 3.3. Ключ недели (`sall`)

Строится конкатенацией (в этом порядке), затем trim:

```
padLeftWithZeros(поле7) + поле6 + поле4 + поле8 + поле9
```

где `padLeftWithZeros` дополняет номер недели нулями слева до 3 символов
(`3` → `003`, `12` → `012`, `123` → `123` без изменений).

Примеры ключей: `0032025011720250113дистанционнаяГП`, `0202025051620250505очная_ЧОС`.

**Все строки с одинаковым ключом недели получают одинаковый номер приказа.**

## 4. Пошаговый алгоритм

### Шаг 0. Подготовка структур данных

- `dicInd: map<string, string>` — ключ недели → номер приказа, который надо присвоить всем строкам с этим ключом (заполняется по мере обхода; первое встреченное значение поля 11 «побеждает»).
- `dicMas: map<string, array<char>[100]>` (глобальная) — ключ = номер недели в формате `003`; значение = массив из 100 символов, где `'+'` на позиции `K-1` означает «номер `K` на этой неделе уже занят». Инициализация нового массива: нули, позиция `[0] = '_'`.
- `maxNomInNedel: int[100]` — максимальный занятый номер `K` для каждой недели (индекс = номер недели).
- `masSall: map<string, string>` — ключ недели → trim(поле 11) последней обработанной строки с этим ключом.
- `masOk: string[]` — строки, подготовленные к сортировке.

### Шаг 1. Чтение и проверка файла

1. Прочитать файл целиком, разбить на строки.
2. Если строк нет — сообщение «Входной файл пуст», **код 5**.
3. Если первая строка начинается с BOM (`EF BB BF`) — удалить эти 3 байта из первой строки.

### Шаг 2. Цикл инициализации (первый проход по строкам)

Для каждой строки (в блоке try — любая ошибка данных → код 2, см. шаг 2.1):

1. Если `trim(строка)` пуст — пропустить.
2. Разбить строку по `|` → `masFields`.
3. Если полей < 12 — **ошибка данных** «Мало полей (N) в строке: ...» → код 2.
4. **Фильтрация:** если поле 10 НЕ является номером удостоверения И не содержит подстроку `правка` — пропустить строку.
   - «Номер удостоверения» (`tstIsUd`): строка содержит **ровно 9 цифр** (остальные символы любые, подсчёт только цифр).
   - Проверка подстроки `правка` покрывает слово «Справка» (регистрозависимо, как в оригинале).
5. Вычислить ключ недели `sall` (см. 3.3).
6. Взять `rawNomerPrik = поле 11`; извлечь из него последнее число `nomPrNaNed` (`getLastNumber`: разбить по `_`, взять последний кусок, распарсить как int; пустая строка или не число → −1).
7. Если `nomPrNaNed > 0` — отметить номер занятым: `markNumber(padLeftWithZeros(поле7), nomPrNaNed)`, т.е. `dicMas[key][nomPrNaNed-1] = '+'` (номера вне 1..100 игнорируются; при первом обращении массив создаётся, `[0]='_'`).
8. Если `sall` ещё нет в `dicInd` — `dicInd[sall] = rawNomerPrik` (запоминается **первый** встреченный номер для ключа, даже пустой).
9. Валидация недели: `nNedel = int(поле7)`; если не в диапазоне 1..99 — **ошибка данных** «Неверный номер недели» → код 2. (Ошибка парсинга int тоже → код 2.)
10. Если `rawNomerPrik` непустой: разбить по `_`; если кусков < 2 — **ошибка данных** «Неверный формат номера приказа» → код 2; иначе `tnom = int(кусок[1])` и обновить `maxNomInNedel[nNedel] = max(maxNomInNedel[nNedel], tnom)`.
11. `masSall[sall] = trim(поле 11)` (перезаписывается — остаётся значение **последней** строки с этим ключом).
12. Сформировать строку для сортировки: `pad60(sall) + "|" + поле0 + "|" + поле11`, где `pad60` — trim, затем дополнение пробелами справа до 60 символов.
13. Если третий символ (`[2]`) этой строки `'?'` — пропустить (неделя не вычислилась — защита от «мусорного» номера недели вида `??3`).
14. Добавить строку в `masOk`.

#### Шаг 2.1. Обработка ошибки данных (код 2)

Сообщение об ошибке формируется из полей **текущей** строки:
- если полей > 6: `поле0|поле1|поле2|поле3|поле4|поле5` + двойной перевод строки + текст исключения;
- иначе если полей > 1: все поля через `|` + текст исключения;
- иначе: только текст исключения.

Заголовок окна: `Ошибка Excel в строке <поле0>` (или `?`, если полей нет). Возврат кода 2.

### Шаг 3. Проверка результата фильтрации

Если `masOk` пуст — сообщение «Нет ни одной строки, пригодной для обработки», **код 6**.

### Шаг 4. Сортировка

Отсортировать `masOk` лексикографически (по возрастанию, побайтово). Благодаря
формату `pad60(ключ)|...` строки группируются по ключу недели, а внутри ключа —
по номеру строки Excel. Номер недели в начале ключа дополнен нулями до 3
символов, поэтому недели сортируются численно.

Побочный эффект (отладка): записать отсортированный массив в файл
`SortMasOk.csv` в каталоге исполняемого файла (строки через `\n`).

### Шаг 5. Второй проход — присвоение номеров и формирование выхода

Для каждой строки `line` из отсортированного `masOk`:

1. `nNed3 = int(line[0..3])` — номер недели; `keyNed3 = line[0..3]` — строковый ключ `"003"`.
2. `nOutPrik = ""`.
3. Разбить `line` по `|` → `mm`. Если кусков < 3 — внутренняя ошибка формата (в оригинале Exception → код 3).
   - `mm[0]` — ключ недели, дополненный пробелами до 60;
   - `mm[1]` — номер строки в Excel;
   - `mm[2]` — сохранённый номер приказа (поле 11 исходной строки).
4. `keyInd = trim(mm[0])`; `saveNomPrik = trim(mm[2])`.
5. **Если `saveNomPrik` пуст** (у исходной строки не было номера приказа):
   - `pi = dicInd.get(keyInd, "")`.
   - **Если `pi == ""`** (для этого ключа ещё не назначен номер — т.е. это первая встреченная строка ключа):
     - Найти «дырку»: если `keyNed3` есть в `dicMas` → `dirka = findFirstUnmarked(dicMas[keyNed3])` (индекс первого символа ≠ `'+'`, +1; если все заняты → −1). Иначе `dirka = 10000` (заведомо больше максимума — дырку не используем).
     - Выбор номера по приоритету (ИСПРАВЛЕННАЯ логика, см. примечание ниже):
       1. **Существующий номер этого ключа**: если `masSall.get(keyInd, "") != ""` → `nOutPrik = masSall[keyInd]` (строки, добавленные задним числом, попадают в уже напечатанный приказ своей группы — это важнее дырок);
       2. **Дырка**: иначе если `0 < dirka <= maxNomInNedel[nNed3]` → `nOutPrik = "{nNed3}_{dirka}"`, и дырка сразу помечается занятой: `markNumber(keyNed3, dirka)` (иначе её же получит другой ключ этой недели — дубль номера приказа);
       3. **Новый номер**: иначе `maxNomInNedel[nNed3] += 1; nOutPrik = "{nNed3}_{max}"`, и он тоже помечается занятым через `markNumber`.
     - Записать `dicInd[keyInd] = nOutPrik` — все последующие строки с этим ключом получат тот же номер.

> **Примечание об исправлении.** В первоначальной D-версии порядок был
> «дырка → masSall → max+1» и присвоенная дырка не помечалась занятой.
> Это давало два дефекта: (а) два разных ключа одной недели с пустыми
> номерами получали одну и ту же дырку (два приказа с одним номером);
> (б) строки, добавленные задним числом к ключу, у которого уже был
> напечатанный номер, получали дырку вместо номера своего приказа.
> Исправлено в обеих версиях (D и DMC); поведение зафиксировано
> тестами `gen_test.py`/`check_holes.py` (недели 9 и 16).
   - **Иначе** (`pi != ""`) → `nOutPrik = pi` (подставить уже назначенный номер).
   - Если же `saveNomPrik` непуст — `nOutPrik` остаётся `""` (номер у строки уже был, новый не назначается).
6. Сформировать выходную строку: `mm[1] + "|" + nOutPrik + "|" + mm[2] + "|" + line`
   (номер строки Excel | новый номер (или пусто) | старый номер | исходная sort-строка целиком, включая pad60-ключ). Добавить в массив выходных строк.

### Шаг 6. Атомарная запись результата

1. Записать выходные строки (через `\n`, **без** финального перевода строки в конце последней) во временный файл `<имя_входного>.tmp`.
2. Если входной файл существует — удалить его.
3. Переименовать `.tmp` в имя входного файла.

Возврат **кода 0**.

### Шаг 7. Глобальная обработка ошибок (обёртка)

Вся работа выполняется под обёрткой:
- ожидаемое исключение (ошибка чтения/записи, `int(...)` от мусора и т.п.) → показать `Ошибка: <текст>`, **код 3**;
- внутренняя/фатальная ошибка (выход за границы массива и т.п.) → показать `Внутренняя ошибка: <текст>`, **код 4**.

## 5. Вспомогательные функции (точные определения)

- `padLeftWithZeros(s)`: длина 1 → `"00"+s`; длина 2 → `"0"+s`; иначе `s`.
- `tstIsUd(s)`: true, если количество цифровых символов в `s` ровно 9.
- `getLastNumber(s)`: пустая строка → −1; иначе последний кусок после разбиения по `_`, распарсенный как int; при ошибке парсинга → −1.
- `findFirstUnmarked(arr)`: индекс первого элемента ≠ `'+'`, +1; если все `'+'` → −1. (В оригинале также печатает массив в stdout — отладочный вывод, при портировании можно убрать.)
- `pad60(s)`: `trim(s)`, дополненный пробелами справа до ширины 60. **Ширина считается в символах UTF-8 (code points), не в байтах** — так работает D `format("%-60s")`; при байтовом подсчёте паддинг ключей с кириллицей не совпадёт с оригиналом (проверено побайтовым сравнением выходных файлов).
- `markNumber(key, number)`: если `number` вне 1..100 — ничего не делать; если ключа нет в `dicMas` — создать массив 100 символов с `[0]='_'`; установить `[number-1]='+'`.
- `showError(msg, title="outputPrik")`: показать сообщение (перекодировка UTF-8 → CP1251 для MessageBoxA; при портировании — любой видимый пользователю канал).

## 6. Важные замечания для портирования

1. **Порядок сортировки — побайтовый/лексикографический** по строке `pad60(ключ)|строкаExcel|поле11`. Ключи содержат кириллицу (`очная`, `дистанционная`), поэтому порядок сравнения зависит от кодировки: в оригинале сравниваются UTF-8 байты. На целостность группировки это не влияет, но влияет на то, **какая строка ключа будет первой** (а значит, чей `dicInd`-номер победит и в каком порядке искаться дырки/max+1). Воспроизводите сравнение по UTF-8 байтам (кодовым точкам), а не по locale.
2. **`dicInd` хранит первое встреченное значение** поля 11 для ключа (даже пустое); `masSall` — последнее. Обе структуры участвуют в выборе номера — сохраняйте эту семантику.
3. **Строки с уже заполненным номером (поле 11)** получают пустой `nOutPrik` во втором проходе, но их номера всё равно учитываются в `dicMas`, `maxNomInNedel` и `dicInd` на первом проходе.
4. **Дырки** ищутся только среди номеров `<= maxNomInNedel` недели; если дырки нет — берётся `max+1`. Нумерация номеров внутри недели начинается с 1.
5. Номер недели валиден только 1..99 (ошибка данных иначе); номер приказа `K` в `dicMas` учитывается только в диапазоне 1..100.
6. Кодировка файла — UTF-8 (с опциональным BOM); переносы строк в выходном файле — `\n`.
7. Зависимость `asc1251.d` нужна только для перекодировки сообщений MessageBox (UTF-8 → Windows-1251) — в переносимой версии не требуется.
8. Известные особенности оригинала (решить, воспроизводить ли): GUI-версия берёт `args[1]` вместо `args[0]`; `findFirstUnmarked` печатает массив в stdout; отладочный файл `SortMasOk.csv` пишется рядом с exe; в выходную строку включается исходная sort-строка с пробельным паддингом до 60 символов.
