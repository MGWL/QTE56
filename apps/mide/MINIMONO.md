# MiniMono 6.1 — архитектура и справка (глава из документации MiniM)

> ↑ Навигация: [AGENTS.md](../../AGENTS.md) → [apps/mide/README.md](README.md)
>
> Источник: официальная документация MiniM Database Server, глава 6 «MiniMono».
> MiniMono — короткое название однопользовательской редакции **MiniM Embedded
> Edition** — DLL с модулями сервера MiniM для внедрения MUMPS в приложение.
> В проекте используется в `d/mumps.d` (обёртка MumpsVM) и `apps/mide/`.

## 6.1. Архитектура MiniMono

MiniM Embedded Edition представляет собой библиотеку динамической компоновки
с модулями сервера MiniM. Предназначена для внедрения в приложение возможностей
языка MUMPS и функций MiniM. **Поддерживается только редакция Windows 32 бит.**

Приложение создаёт виртуальную машину MiniMono, обращается к ней для выполнения
команд, вычисления выражений и изменения переменных. В контексте хост-процесса
MiniMono работает как процесс MiniM и несколько демонов (демон расширения БД,
демон записи изменённых блоков, демон журнала — запускаются, если определено
в данных инициализации). Все задачи работают в дочерних вторичных потоках.
VM работает с **одной базой данных** в формате MiniM Database Server.

Доступны все возможности полного сервера, кроме запуска фоновых процессов и
многофайловой базы. Полный сервер работает на уровне стабильности ОС +
восстановление по предзаписи и из бекапа с журналом; MiniMono — только на
уровне стабильности хост-приложения + восстановление по предзаписи или из
бекапа (гвардианов процессов нет). Горячий бекап поддерживается.

**Последовательность работы:** 1) получить значения инициализации по умолчанию,
2) скорректировать под приложение, 3) создать VM, 4) обращение к СУБД,
5) завершение работы.

**Ключевые ограничения:**
- MiniMono не хранит настроек — их хранит хост-приложение.
- Одна VM = одна БД; несколько VM с одной БД работать не должны.
- **В одном хост-приложении — только одна VM MiniMono.**
- Нет собственного UI: создаётся виртуальное устройство DLL, а приложение
  объявляет его обработчики событий (консольное/оконное — неважно).
- VM работает с БД как сервер MiniM с базой «%SYS». Рекомендуется готовить
  БД на отдельном инструментальном экземпляре MiniM Database Server.
- Отладчик не поддерживается.

**Утилиты в комплекте:** minimonostd.exe (stdin/stdout), minimonocon.exe
(консоль), minimonore.exe (редактор рутин: компиляция, экспорт/импорт рутин,
байткода, глобалов), minimonoge.exe (редактор глобалов), minimne.exe
(редактор файлов определения символов).

Инсталляция: достаточно скопировать `minimono.dll` в каталог, доступный хост
приложению. Регистрация не требуется. Лицензирование не требуется (бесплатно).

## 6.2. Структуры данных

Те же, что у модулей ZDLL, те же соглашения о кодировании.

- **MINIM_STR** — передача значений (байты или числа; тип — в служебном поле
  `len`/`type`). Можно аллокировать не всю структуру, а только значимую часть.
  Хост создаёт структуры в своей памяти; при вызове хоста из MiniMono VM
  предоставляет указатели на свои внутренние структуры.
- **ZDLLCB** — структура указателей на функции контекста MiniM. Для ZDLL это
  структура обратного вызова, для хост-приложения — прямого. Создаётся при
  создании VM.
- **MINIMONOVM** — параметры инициализации VM. Все поля, кроме `cbfunc`,
  заполняет хост; `cbfunc` заполняет VM (реальные указатели на свои функции).
  Есть функция заполнения значениями по умолчанию.

Поля MINIMONOVM (значение по умолчанию):

| Поле | Назначение | Умолчание |
|---|---|---|
| DataFile | имя файла БД (полный/относительный путь) | пусто — указать обязательно |
| ReadOnly | 1 = только чтение (демоны записи не запускаются) | 0 (запись разрешена) |
| JournalingEnabled | журналирование глобалов; 0 = нет демона журнала, откат транзакций невозможен | 1 |
| LockAreaSize | таблица блокировок lock, МБ | 1 |
| RoutineCacheSize | кеш байткода, МБ | 1 |
| DeviceTableSize | число устройств ввода-вывода | 4 |
| DeviceNameSize | длина имени устройства | 400 байт |
| DBCacheSize | кеш глобалов, МБ (учитывать адресное пространство хоста) | 100 |
| NullSubscripts | разрешить пустые индексы | 0 (ошибка) |
| TransactLevelLimit | макс. вложенность транзакций | 255 |
| TrapOnEof | ошибка `<ENDOFFILE>` при EOF | 1 |
| FrameCount | макс. стеков вызовов/xecute | 1024 |
| JournalCache | кеш журнала, МБ | 4 |
| LocaleFileName | файл определения символов | NULL (по умолчанию) |
| ProcessStorage | пространство локальных переменных, МБ | 8 |

Обработчики устройства DLL по умолчанию — нулевые указатели; если указаны —
вызываются M-программой при обращении к устройству DLL.

## 6.3. Прямой вызов

Для выполнения команд, вычисления выражений, преобразования данных, операций
с локальными/глобальными переменными, вызова подпрограмм. Хост размещает
структуры параметров и приёма данных в своей памяти; отдельных функций
аллокации нет. Интерфейс совпадает с ZDLL (номера ошибок с префиксом ZDLL).
После завершения VM обращение по указателям `cbfunc` запрещено.

## 6.4. Обратный вызов

M-программа при работе может обратиться к устройству DLL — VM вызывает
обработчики хоста (не указан → действие по умолчанию). Структуры данных
принадлежат VM — **модифицировать их нельзя**. Обработчики возвращают 0 при
успехе, не 0 — VM генерирует ошибку. Обработчики могут сами обращаться к
контексту VM.

- `dlldevreadstr_t` / `dlldevreadchar_t`: таймаут в миллисекундах (не указан → -1);
  длина чтения не указана → -1.
- Реакция на EOF согласуется хостом между функциями чтения и обработчиком EOF
  (может вызываться неоднократно).
- Обработчиков open/close нет: устройство DLL — устройство по умолчанию,
  не создаётся и не закрывается.

## 6.5. Перечень отличий от полного сервера

- Нет гвардианов процессов и внешних настроек (файлы/реестр).
- Не поддерживаются устройства CON, STD, TNT, MEM.
- Автоматически создаются служебные файлы `minim.log`, `minim.bij` (предзапись)
  и журналы **рядом с файлом данных** → базу размещать в отдельном каталоге.
- Команда `JOB` не поддерживается (однопроцессная реализация).
- `$JOB` — номер потока Windows (не процесса); `$ZPARENT` = 0;
  `$ZVERSION` = "MiniMono"; имя инсталляции всегда "MINIMONO".
- Отладчик не поддерживается (многопроцессный в полном сервере).
- Одна БД, только первичный файл (экстенты не поддерживаются), имя всегда
  "%SYS"; отображение глобалов/рутин в другие БД не поддерживается.
- Устройство DLL создаётся автоматически; для неподдерживаемых событий —
  поведение как у NULL-устройства (запись игнорируется, чтение возвращает
  управление немедленно).
- `HALT` завершает **текущее обращение** к VM, а не хост-процесс; обращаться
  можно снова.
- Статистика VM не экспонируется как счётчики Windows, но доступна через
  `$view("perf")`.

## Привязка к коду проекта

- Инициализация MINIMONOVM и загрузка `minimono.dll`: `src_m/minimono.d`,
  `src_m/zdll.d` (структуры MINIM_STR/ZDLLCB), вызов в `apps/mide/mide.d`.
- Высокоуровневая обёртка `MumpsVM` (set/get/exists/children/inc/eval,
  UTF-8↔cp1251 через QTextCodec): `d/mumps.d`.
- Служебные файлы рядом с БД подтверждаются: `apps/mide/dbek.dat.bij`.
- Серверный режим (MNM* через `minimsc.dll`) в MumpsVM не реализован —
  только локальная VM.
