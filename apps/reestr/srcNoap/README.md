# noap_0018 — загрузка свидетельств в NOAP.mdb (QTE56, v4)

GUI на биндингах QTE56 (D + Qt 5.13.2, 32-bit). UI строится кодом, без .ui-файлов.
Образец архитектуры — `../reestr.d`.

## Файлы

- `noap_0018.d` — main, построение UI, слоты.
- `noap_ini.d` — `Config` + load/save через QSettings (IniFormat);
  при отсутствии INI создаёт дефолтный.
- `noap_log.d` — цветной лог поверх QTextEdit (read-only):
  `logInfo/logOk/logWarn/logError`, цвета info/ok/warn/error, метка времени,
  дублирование в stdout.
- `noap_csv.d` — парсер/валидатор CSV-строк (`parseText`, `CsvRow`:
  ошибки/предупреждения, пропуск заголовка и комментариев).
- `noap_mdb.d` — подключение к NOAP.mdb (QODBC, DSN-less), справочники
  в память при старте (ATTVID/ATTLEVEL/Method_K/Objects_K/Settings),
  проверка колонок строки по справочникам (`checkRowRefs`), проверки по базе
  (`checkRowDb`, noap.md §9), запись строк (`insertRow`, noap.md §6–§8).
- `noap_mssql.d` — чтение обращений из центральной db-docs (MS SQL, QODBC,
  DSN из INI [CentralDB]) по №направления → CSV-строки во входное окно.
- `noap_organ.d` — модальная форма справочника ORGAN: фильтр, таблица,
  добавление/редактирование/удаление (удаление запрещено при ссылках
  из ANKETA.ORG_RAB / ATTEST.OrgZajav).
- `makefile` — сборка через Digital Mars Make (`make`, `make clean`).
- `build.bat` — обёртка над `make`.
- `CSV_FORMAT.md` — спецификация формата входных CSV-строк (разделитель `|`,
  20 колонок) для загрузки свидетельств; маппинг колонок на таблицы NOAP.mdb.
- `example_certificates.csv` — образец входных данных в этом формате.

## Сборка

```
cd apps/reestr/srcNoap
make          :: или: build.bat
make clean    :: удалить exe и obj
```

Результат: `apps/reestr/noap_0018.exe` (консольный режим — stdout лога виден;
для релиза добавить `-L/SUBSYSTEM:WINDOWS -L/ENTRY:mainCRTStartup`).

## Запуск

```
cd apps/reestr
noap_0018.exe
```

Нужен развёрнутый runtime QTE56 в PATH (Qt5*.dll из `bin513`, qte56_*.dll).
qte56_*.dll подхватываются и по пути от exe (`../../dll/dll32` + SetDllDirectoryW).

При первом запуске рядом с exe создаётся `noap_0018.ini`
(секции `[MDB]`, `[CentralDB]`, `[Input]`, `[UI]`; в `[UI]` — SplitterState,
FontName/FontSize — моноширинный шрифт входного окна, по умолчанию Hack 10).

## Реализовано в v2

- QMainWindow: меню («Файл» → «Выход», «Справочники» → «Организации (ORGAN)»,
  «Справка» → «О программе»), тулбар («НомерСтрок» / «Анализ» / «Запись» /
  «Организации» / «Очистить» / «Выход»), панель «Направление»
  (QLabel + QLineEdit + QPushButton «Читать из Базы»), входное окно
  (QPlainTextEdit, моноширинный шрифт из INI, без переноса строк,
  горизонтальный/вертикальный скроллеры), цветной лог (QTextEdit),
  вертикальный QSplitter, QStatusBar.
- «НомерСтрок» — переключатель нумерации строк входного окна: префикс
  `NNN--` (3 цифры с ведущими нулями) добавляется/снимается; на парсинг
  не влияет (парсер префикс снимает).
- «Анализ» — разбор CSV-строк по CSV_FORMAT.md (модуль `noap_csv.d`):
  пропуск пустых/комментариев/заголовка, проверка числа колонок (20),
  корректности дат (ДД.ММ.ГГГГ, реальная дата) и формата SvNo
  (`0018-YY-XXXXX` или `0018-XXXXX`); цветной построчный отчёт и итог в логе.
- «Очистить» очищает входное окно; «О программе» — версию в лог.
- Пропорции сплиттера сохраняются в INI при закрытии окна и
  восстанавливаются при старте (`UI/SplitterState`).

## Реализовано в v3

- Подключение к NOAP.mdb при старте (QODBC, DSN-less; `noap_mdb.d`),
  справочники в память (ATTVID/ATTLEVEL/Method_K/Objects_K/Settings).
- «Анализ»: дополнительно проверки по справочникам в памяти и по базе
  (noap.md §9): хвост XXXXX, ФИО+дата рождения, голограмма, ИНН/ORGID;
  дубли ИНН — двухцветный построчный список кандидатов (`logPair`).
- «Запись» (тулбар, с подтверждением QMessageBox): вставка строк без ошибок
  по noap.md §6–§8 — JOB_POSITION, ANKETA, ATTEST, ATT_METHODK, ATT_OBJECTK;
  транзакция на строку, откат при ошибке. ORGAN только читается: организация
  обязана существовать (ИНН/ORGID), автодобавления нет — новую организацию
  вносит только пользователь (справочник «Организации (ORGAN)»).

## Реализовано в v4

- «Читать из Базы» (`noap_mssql.d`): чтение обращений из db-docs по
  №направления (ввод `17` = `17` + `17/*`, `17/2026` — точно) → готовые
  CSV-строки дописываются во входное окно. Подключение ленивое, по [CentralDB]
  из INI (QODBC, DSN db-docs). SQL-2000-совместимо.
- Справочники Method_K/Objects_K — только действующие периоды
  (Method_K ID>5000 «с янв.2021», Objects_K ID>30000 «с фев.2021»);
  коды старых периодов при анализе дают ошибку.
- Справочник ORGAN (`noap_organ.d`, меню «Справочники» / кнопка тулбара):
  модальный диалог — фильтр (наименование/ИНН), таблица организаций,
  «Добавить»/«Редактировать» (форма из 15 полей), «Удалить» (запрещено при
  ссылках из ANKETA/ATTEST), «Обновить».

## Реализовано в v5

- ИНН организации обязателен: пустая колонка 16 — ошибка анализа; ИНН,
  отсутствующий в ORGAN, — тоже ошибка (автодобавление организаций убрано,
  новую организацию вносит только пользователь через справочник ORGAN).
- `attestToCsv(attId)` (`noap_mdb.d`) — выгрузка записи ATTEST в CSV-строку
  формата входного окна (20 колонок, только чтение): ATTEST + ANKETA +
  JOB_POSITION + ORGAN + ATT_METHODK + ATT_OBJECTK. Объекты выводятся
  листьями со свёрткой zmasall (`2.*` и т.п.), ИНН — без `/ORGID`,
  колонка 1 (Код_обращения) пустая — в MDB её нет. Основа отчёта контроля
  введённых записей.
- CLI-режим для теста выгрузки (без GUI): `noap_0018.exe --csv 27681`
  или список `--csv 27681,27682` — строки в stdout (кириллица: `chcp 65001`).
- Меню «Файл» → «Отчёт по записям…» (`noap_report.d`): модальный диалог
  периода из двух дат (начало входит, окончание — нет, проверка формата
  и d1 < d2), затем выборка `ATTEST` по `SvDateVyd` в [д1; д2)
  (`attestIdsByDateVyd`) и выгрузка каждой записи через `attestToCsv` —
  строки дописываются во входное окно с комментарием-заголовком `# Отчёт …`.
- QRadioButton «Отключить контроль ошибок» (внизу окна, над QStatusBar;
  по умолчанию выключен). При активном флаге «Запись» пишет и строки
  с ошибками контроля (в лог — WARN по каждой такой строке и в диалоге
  подтверждения). Структурно битые строки (колонок ≠ 20) пропускаются
  всегда. Особый случай: непервичная аттестация, человек не найден
  в ANKETA — при отключённом контроле пишется по алгоритму первичной
  (создаётся новая персона), но AttVid ставится из исходной строки
  (`insertRow(cols, dbr, noCtrl)`).
- Все `QSqlQuery` в `noap_mdb.d` освобождаются явным `q.clear()` сразу
  после использования — иначе GC держит statement-хэндлы слишком долго
  и Jet падает с «Открытие большего числа таблиц невозможно» на больших
  пачках (отчёт/анализ/запись сотен строк).
- «НормОб»: диапазоны объектов верхнего уровня `N-M` (`1-12`, `1-3, 8-11`)
  разворачиваются в последовательность 1..12 (`expandTopRange` в spnorm2.d,
  вызов в `fromNoapToEk87`). Код-лист `12` (потомков в таблице 440-02 нет)
  больше не превращается в мусорный `12.*` — `hasChildren440` решает,
  добавлять ли `.*`.
