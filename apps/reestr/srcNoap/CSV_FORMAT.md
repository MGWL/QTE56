# CSV_FORMAT.md — формат обмена для загрузки свидетельств в NOAP.mdb

Формат входных строк приложения `noap_0018` для вставки/анализа записей о свидетельствах
(аттестациях) в базу `apps/reestr/noap/DB/NOAP.mdb`. Основа — выгрузка `apps/reestr/napr.csv`,
адаптированная под полную вставку по алгоритмам `apps/reestr/noap/noap.md` §6–§8.

- Разделитель колонок: **только `|`** (вертикальная черта). Символ `|` внутри значений запрещён.
- Кодировка файла/буфера: **UTF-8**.
- Первая строка — **обязательный заголовок** (имена колонок как в §1, порядок фиксирован).
- Пустые строки и строки, начинающиеся с `#`, игнорируются.
- Строки могут быть пронумерованы префиксом `NNN--` (кнопка «НомерСтрок»,
  например `001--155440|0018-01-23001|...`) — парсер префикс снимает,
  на разбор он не влияет.
- Даты: `ДД.ММ.ГГГГ` (например `22.06.2026`). Пустое значение любой колонки = NULL.
- Списки значений внутри одной колонки (Метод, Список_объектов) — через запятую, без пробелов
  или с пробелами (парсер обрезает): `6,8,11`, `6.4, 6.5, 6.6`.

## 1. Заголовок и порядок колонок (20 колонок, 19 разделителей)

```
Код_обращения|Номер_удостоверения|Фамилия|Имя|Отчество|Дата_рождения|Пол|Вид_аттестации|Уровень|Дата_обращения|Дата_выдачи|Срок_действия|Метод|Список_объектов|Голограмма|ИНН_организации|Наименование_организации|Адрес_юридический|Адрес_почтовый|Должность
```

## 2. Семантика колонок и маппинг на NOAP.mdb

| # | Колонка | Обяз. | Формат / значения | Назначение в MDB |
|---|---------|-------|-------------------|-------------------|
| 1 | Код_обращения | да | целое | В MDB **не пишется**. Идентификатор строки из db-docs (`Обращения.Код_обращения`); кнопка «Читать из Базы» выбирает обращения из центральной БД по **№направления** |
| 2 | Номер_удостоверения | да | `0018-YY-XXXXX` или `0018-XXXXX` | `ATTEST.SvNo`. Вводится оператором целиком: 0018 — код центра, YY — филиал (может отсутствовать), XXXXX — номер, назначенный комиссией. Проверки — noap.md §5, §9 |
| 3 | Фамилия | да | текст, им. падеж | `ANKETA.FAM` + ключ поиска персоны (§9) |
| 4 | Имя | да | текст | `ANKETA.NAM` + ключ поиска |
| 5 | Отчество | да* | текст, может быть пустым у иностранцев | `ANKETA.OT` + ключ поиска |
| 6 | Дата_рождения | да | ДД.ММ.ГГГГ | `ANKETA.DTR` + ключ поиска персоны (§9) |
| 7 | Пол | нет | `М` / `Ж` | `ANKETA.SEX`; пусто = NULL. «Читать из Базы» ставит `?` (в db-docs пола нет) — `?` не проходит валидацию, оператор обязан исправить вручную |
| 8 | Вид_аттестации | да | см. §3.1 | `ATTEST.AttVid` → ATTVID.ID |
| 9 | Уровень | да | `1`/`2`/`3` или `I`/`II`/`III` | `ATTEST.LEV` **и** `ATTEST.LEVZ` (заявленный = присвоенный) → ATTLEVEL.ID, см. §3.2 |
| 10 | Дата_обращения | да | ДД.ММ.ГГГГ | `ATTEST.DataZajav` |
| 11 | Дата_выдачи | да | ДД.ММ.ГГГГ | `ATTEST.SvDateVyd` (в napr.csv — колонка d1) |
| 12 | Срок_действия | да | ДД.ММ.ГГГГ | `ATTEST.SvDateFin` (в napr.csv — d2 / Срок_действия_уд) |
| 13 | Метод | да | коды РУС через `,`: `ЭК`, `РК`, `УК`, ... | `Method_K` → строки `ATT_METHODK(ATT_ID, METHODK_ID)`. Минимум 1 метод |
| 14 | Список_объектов | да | коды через `,`: `6,8,11`, `6.4,6.5,6.6` | `Objects_K.CODE` → строки `ATT_OBJECTK(ATT_ID, OBJECTK_ID)`. Минимум 1 объект |
| 15 | Голограмма | да | до 10 символов | `ATTEST.hologram`; `0` = допустимый фиктивный номер. Уникальность контролируется (§8) |
| 16 | ИНН_организации | да | `ИНН`, `ИНН/ORGID` или `/ORGID` | `ORGAN.INN` + ключ поиска организации. Пусто — ошибка; ИНН, отсутствующий в ORGAN, — ошибка (автодобавления нет, организацию добавляет только пользователь). В ORGAN бывают дубли ИНН — выбор конкретной записи запоминается кодом ORGID после `/` (см. §5.1) |
| 17 | Наименование_организации | да | текст | `ORGAN.ORGNAME` (справочно, для сверки с найденной записью) |
| 18 | Адрес_юридический | нет | текст | `ORGAN.IND`+`ADRES` (при вставке: вся строка в ADRES) |
| 19 | Адрес_почтовый | нет | текст | `ORGAN.INDP`+`ADRP` (аналогично) |
| 20 | Должность | нет | текст | `ANKETA.APPOINTMENT` → JOB_POSITION.ID; отсутствующая должность добавляется в справочник (noap.md §6 п.4) |

Исключены из формата (были в napr.csv): `рег_номер` (дублирует Код_обращения),
`Тип_сертификата`, `Направление`, `Поток` — в MDB полей нет, не переносятся.

## 3. Справочные маппинги

### 3.1. Вид_аттестации → ATTEST.AttVid (ATTVID)

| Значение в CSV (регистр не важен) | ID | Код |
|---|---|---|
| первичная | 1 | ПЕРВ |
| повторная | 2 | ПОВТ |
| расширение | 3 | РАСШ |
| аннулирование | 4 | АННУ |
| приостановка | 5 | СРОК |
| продление | 6 | ПРОД |

### 3.2. Уровень → ATTEST.LEV / LEVZ (ATTLEVEL, APP='NOAP')

В базе `CODE` уровней НОАП — арабские цифры («1», «2», «3», NAME = «I уровень»...);
в CSV допускаются и арабские, и римские.

| CSV | ID | Код в базе |
|---|---|---|
| 1, I | 3 | CODE='1', I уровень |
| 2, II | 4 | CODE='2', II уровень |
| 3, III | 5 | CODE='3', III уровень |

### 3.3. Метод → Method_K

Колонка содержит русские коды методов НК (`ЭК`, `РК`, `УК`, `МК`, `ВК`, `ПВК`, `ВИК`,
`НДС`, `УФ НК`, ...). Программа при старте читает справочник Method_K в память и ищет
по коду/краткому имени (без учёта регистра). Учитываются **только действующие записи
(ID > 5000, период «с янв.2021»)** — коды старого периода (ID 4xxx) считаются
несуществующими. Код не найден → ошибка строки.

### 3.4. Список_объектов → Objects_K

Колонка содержит коды пунктов (`6`, `6.4`, `8`, `11`, ...) — это `Objects_K.CODE`
(справочник в памяти, поиск по CODE; завершающая точка кода в базе — `'1.12.'` —
игнорируется). Учитываются **только действующие записи (ID > 30000, период
«с фев.2021»)** — коды старых периодов (ID 1xxxx/2xxxx) считаются несуществующими.
Код не найден → ошибка строки.

## 4. Значения по умолчанию (полей в CSV нет, задаются программой)

| Поле ATTEST | Значение |
|---|---|
| `AttTyp` | 5 (СНК, «Специалисты НК») |
| `Result` | 2 (СДАЛ/Аттестован) |
| `NOA` | 2 |
| `SUMMA` | 0 |
| `WithVAT` | False |
| `Prot_ID` / `ProtDate` | NULL (протокол не используется, noap.md §10) |
| `ProtNum` | `'000'` |

При вставке новой организации: `IsNOAP=False`, остальные поля — из колонок 16–19.
При вставке новой персоны: падежные формы (FAMR/NAMR/OTR/FAMD/NAMD/OTD) — пустые строки,
`OBRID`=NULL (noap.md §6).

## 5. Валидация строки (до обращения к БД)

1. Ровно 20 колонок (19 разделителей `|`).
2. Обязательные колонки (1–6, 8–15, 17) не пусты; Отчество может быть пустым.
3. Даты (6, 10, 11, 12) соответствуют ДД.ММ.ГГГГ и являются корректными датами;
   `Срок_действия` > `Дата_выдачи`.
4. `Номер_удостоверения` соответствует шаблону `0018-YY-XXXXX` (группы 4-2-5 цифр)
   или `0018-XXXXX` (без указания филиала, группы 4-5 цифр); иные формы
   (исторические 9–10 символов и пр.) — только предупреждение.
5. `Вид_аттестации` и `Уровень` — в таблицах §3.1/§3.2.
6. `Метод` и каждый элемент `Список_объектов` находятся в справочниках в памяти.
7. Дубликаты `Номер_удостоверения` и пары (ФИО+Дата_рождения) внутри самой пачки —
   предупреждение/ошибка в зависимости от вида аттестации.
8. `ИНН_организации`: обязательно не пусто (пусто — ошибка): `ИНН`, `ИНН/ORGID`
   или `/ORGID`; после `/` — только цифры (иначе ошибка).
   ИНН не из 10/12 цифр — предупреждение.

### 5.1. Дубли ИНН в ORGAN — ссылка `ИНН/ORGID`

В ORGAN встречаются разные организации с одинаковым ИНН. Семантика колонки 16:

- `5072703668` — поиск по ИНН: одна запись → она и берётся; **несколько →
  предупреждение со списком кандидатов** (ORGID + наименование + адрес);
  если ни одно наименование не совпало точно с колонкой 17 — ошибка
  «уточните выбор кодом ORGID»; **ни одной записи → ошибка** (ИНН отсутствует
  в ORGAN; автодобавления нет — организацию добавляет только пользователь);
- `5072703668/1152` — точная ссылка на запись ORGAN.ORGID=1152; при анализе
  проверяется, что запись существует и её INN совпадает с указанным
  (несовпадение — ошибка);
- `/1152` — ссылка по коду без ИНН (организация без ИНН);
- пусто — **ошибка** (поле обязательное).

## 6. Проверки по базе (после валидации) — noap.md §9

- Первичная (`Вид_аттестации=первичная`): хвост XXXXX не должен быть занят другим
  человеком; человек с такими ФИО+Дата_рождения не должен существовать в ANKETA.
- Непервичная: человек обязан существовать в ANKETA; его прежние записи ATTEST должны
  иметь тот же XXXXX.
- Голограмма: `SELECT ... WHERE hologram=:h` — дубль = предупреждение (кроме '0').
- Организация: ИНН (или ORGID из ссылки `/ORGID`) обязан существовать в ORGAN —
  иначе ошибка. Приложение организации **не добавляет**: новую организацию
  в ORGAN вносит только пользователь (вручную, noap.md §7).

## 7. Пример

См. `example_certificates.csv` в этом каталоге (4 строки, переложенные из napr.csv;
SvNo, даты рождения и даты выдачи в примере **условные**).

Первая строка примера разобрана:

```
155440|0018-01-23001|Колядов|Дмитрий|Алексеевич|15.03.1985|М|первичная|2|01.06.2026|22.06.2026|22.06.2029|ЭК|6,8,11|0||Газпром шельфпроект||119071, г.Москва, ...|
```

→ обращение 155440; SvNo `0018-01-23001`; персона Колядов Д.А., род. 15.03.1985, муж.;
первичная аттестация, II уровень (ATTLEVEL.ID=4); заявка 01.06.2026, выдано 22.06.2026,
действует до 22.06.2029; метод ЭК; объекты 6, 8, 11; голограмма фиктивная;
работодатель «Газпром шельфпроект» (ИНН нет, юр. адрес нет, почтовый задан);
должность не указана.
