# AI Loading Order — Порядок загрузки файлов QTE56

> ↑ Навигация: [AGENTS.md](AGENTS.md)

**Назначение:** Инструкция для AI моделей (Claude, Qwen-Coder, GPT, и др.) по эффективному изучению QTE56 SDK перед написанием приложения.

**Цель:** Получить **рабочее приложение с первой попытки** без crashes от GC, ошибок @live, или неправильного использования API.

---

## 🎯 Принцип

Файлы упорядочены **от обязательных к специализированным**. Не загружай всё подряд — это съест контекстное окно. Читай только то, что относится к текущей задаче.

```
ФАЗА 1 (всегда): Правила + архитектура       ← ОБЯЗАТЕЛЬНО
ФАЗА 2 (всегда): Базовый паттерн             ← ОБЯЗАТЕЛЬНО
ФАЗА 3 (по задаче): Конкретный модуль         ← Только нужный
ФАЗА 4 (по задаче): Примеры из test/          ← Только нужные
ФАЗА 5 (проверка): Контрольный список         ← Перед сдачей
```

## ФАЗА 1: КРИТИЧЕСКИЕ ПРАВИЛА (читать ВСЕГДА, ПЕРВЫМИ)

### 1.1 — `LIVE_QUICKSTART.md` ⚠️ ОБЯЗАТЕЛЬНО

**Что узнаешь:**
- Что такое `@live` и зачем нужен
- **КРИТИЧЕСКОЕ Правило 5:** `@live` ТОЛЬКО для локальных `auto`, НЕ для полей класса
- Паттерны: окно с кнопкой, layout, диалоги
- Как НЕ ловить Access Violation

**Без этого:** твоё приложение упадёт с `object.Error@(0): Access Violation` при первом же `class { Q... _field; ... }`.

### 1.2 — `CLAUDE.md` (если есть в директории проекта)

**Что узнаешь:**
- Соглашения текущего проекта (язык комментариев, build-команды)
- User preferences (Python 3.8, кириллица в комментариях)
- Локальные gotchas

**Без этого:** напишешь стиль, который не примет пользователь.

## ФАЗА 2: БАЗОВАЯ АРХИТЕКТУРА (читать ВСЕГДА)

### 2.1 — `AI_CORE.md`

**Что узнаешь:**
- Загрузка DLL: `LoadQt("./dll")` ДО создания объектов
- `pFunQt[25000]` — таблица функций
- Жизненный цикл: `app.exec(); app.deleteApp();` (НЕ `UnloadQt()`)
- Принцип `getWH()` для родительских аргументов
- `disown()` — когда нужно (только для void* API)

### 2.2 — `AI_SIGNALS_REF.md`

**Что узнаешь:**
- ESlot паттерн: `new ESlot(w.getWH()); sl.set(cb); w.connect_xxx(sl);`
- Прямые сигналы: `w.onItemClicked(cb)`
- События: `onMousePress`, `onKeyPress`, `onResize`, `onClose`
- Сигнатуры коллбэков: `extern(C) void cb(void* dthis, int n, int val)`

**Без этого:** обработчики событий не будут работать или дадут crash.

## ФАЗА 6: КОНТРОЛЬНЫЙ СПИСОК ПЕРЕД СДАЧЕЙ

Перед тем как считать код готовым, проверь:

### Checklist @live

- [ ] **Все локальные** Qt объекты с `@live auto`:
      `@live auto btn = new QPushButton("OK");` ✓
- [ ] **Поля класса БЕЗ** `@live`:
      `_btn = new QPushButton("OK");` ✓ (НЕ `@live _btn = ...`)
- [ ] **Глобальные переменные БЕЗ** `@live`:
      `_db = new QSqlDatabase(...);` ✓ (НЕ `@live _db = ...`)
- [ ] `@live auto app = new QApplication();` есть в `main()`
- [ ] `LoadQt("./dll")` вызван ДО создания QApplication
- [ ] `app.exec(); app.deleteApp();` в конце main
- [ ] **НЕ вызывается** `UnloadQt()`

### Checklist архитектуры

- [ ] `void main()` (не `extern(C) int main()`)
- [ ] Все `gen_q*` модули импортированы
- [ ] Родители передаются через `parent.getWH()`
- [ ] ESlot для сигналов (или прямые `onXxx` для item/row событий)
- [ ] При void* API — `disown()` после addWidget/setLayout
- [ ] Сборка 32-bit (`dmd -m32`)

### Checklist стиля (если есть CLAUDE.md в проекте)

- [ ] Комментарии в D-коде на русском (если требует CLAUDE.md)
- [ ] DDoc для публичных методов с Params/Returns
- [ ] Нет UTF-8 псевдографики в комментариях, кроме коротких "──"

## 🚦 ПРИОРИТЕТЫ ПРИ ОШИБКАХ

Если приложение **компилируется, но падает в runtime**:

1. **Access Violation в конструкторе/методах класса** → проверь @live на полях (правило 5 LIVE_QUICKSTART.md)
2. **Crash при загрузке DLL (error=126)** → DLL отсутствует в `./dll/` или нет зависимостей в PATH
3. **Crash после `app.exec()`** → нет `app.deleteApp()`, или вызван `UnloadQt()`
4. **Crash в коллбэке сигнала** → проверь сигнатуру коллбэка в AI_SIGNALS_REF.md
5. **Crash при работе с layout** → забыл `disown()` для void* API

Если **не компилируется**:
1. Проверь имена полей — `@live` маскирует их (см. правило 5)
2. Проверь импорты `gen_q*`
3. Проверь что DMD 32-bit (`dmd -m32 -i`)
